## Archivar o privatizar

Archivar conserva el codigo y comunica que ya no recibe mantenimiento. Privatizar es la opcion correcta cuando el contenido es material de curso, una copia, una practica demasiado incompleta o no representa el nivel actual.

Archivar primero los repositorios que contienen explicitamente cursos, tutoriales o ejercicios: `curso-master-js-victor-robles`, `Curso-Laravel-devjobs`, `css-complete-guide`, `Curso_React_Todo_El_Contenido_De_cero_a_experto_hooks_y_mern`, `Curso_JavaScriptApp_TodoList`, `curso-VSCode-por-Fernando-Herrera`, `Curso-Laravel-devstagram`, `Curso-Docker`, `Curso-angular-de-cero-a-experto-por-fernando_herrera`, `Curso-Git-Hub-legion-del-mal`, `curso-solidity`, `CryptoZombies`, `Flutter-Movil_cero_a_experto`, `Angular-14-La-Guia-Completa-Proyectos-por-Tomas-Ruiz-Diaz`, `Angular-Avanzado-Lleva-tus-bases-al-siguiente-nivel-MEAN-por-fernando-herrera`, `Angular-Avanzado-Tests`, `Angular-Avanzado-Firebase`, `Angular-Avanzado-Goty`, `REDUX-Angular-NGRX-por-Fernando-Herrera` y `rxjs-de-cero-hasta-los-detalles-por-fernando-herrera`.

Revisar y preferiblemente privatizar los forks y los proyectos con alcance poco propio o demasiado incompleto: `fork--turbo-console-log--afterdelimitter`, `Cartago-CoinGecko_NodeJs-serverless`, `Webpack-predef-config`, `todo-list-react-vite-ts`, `tic-tac-toe-react-page-tutorial-in-ts`, `counter-redux-vite-ts`, `codewars`, `codember-dev`, `minesweeper`, `snake`, `tetris`, `chess`, `basico_php`, `backend_express_mongoose_heroku`, `Certificados` y `design-web-profesional-curso`.

GitHub no ofrece repositorios publicos no listados. Para ocultar realmente uno hay que abrir **Settings > General > Danger Zone > Change visibility** y hacerlo privado. Para archivarlo: **Settings > General > Danger Zone > Archive this repository**. No eliminar repositorios hasta haber comprobado que no alojan una URL, paquete o dependencia activa.

## Mantenimiento por repositorio

Todo repositorio publico que se mantenga debe tener como minimo:

1. Una descripcion de GitHub de una frase y de 3 a 5 temas relevantes.
2. Un README con problema, alcance, arquitectura, requisitos, comandos de ejecucion con Bun cuando aplique, pruebas y estado.
3. Un `LICENSE` adecuado y `.gitignore` sin secretos, binarios locales, archivos de agentes ni resultados de pruebas.
4. Una decision explicita: activo, mantenido, archivado o privado.

La calidad del README, las pruebas y la documentacion de decisiones es mas valiosa en este perfil que añadir mas insignias.
